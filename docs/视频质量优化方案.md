# 视频质量优化方案

> 分析日期：2026-02-28
> 覆盖范围：视觉渲染、文本旁白、语音合成、叙事结构、注意力管理

---

## 一、视觉质量

### 1.1 排版与字体

#### 当前状态

- 标题字号根据文本长度自适应（56–82px）
- `useScale` 基于 1920×1080 设计稿进行全局缩放，最小比例 0.8
- 行高：正文 1.5–1.7，标题 1.3
- 字体：学术主题用系统字体，科普主题用 Noto Sans SC

#### 问题

| 问题 | 影响 | 涉及组件 |
|------|------|----------|
| 多个组件未使用 `useScale` | 不同预设下字号不一致 | BulletList、AnimatedText、HighlightText、FormulaBlock |
| FormulaBlock 使用固定 `fontSize = 26` | 公式在竖屏下过小 | FormulaBlock |
| BulletList `gap: 16` 未缩放 | 竖屏下间距过紧 | BulletList |
| 学术和科普主题使用不同字体族 | 中文在两个主题下观感差异大 | 全局 |

#### 优化方案

1. **统一 Scale 适配**：所有组件的像素值（fontSize、gap、padding、translateX/Y）必须经过 `s()` 缩放
2. **字体统一策略**：两个主题统一使用 Noto Sans SC 作为中文字体，仅正文英文和装饰性字体有差异
3. **动态字号算法**：将标题/正文的字号自适应逻辑抽取为 `useAdaptiveFontSize(text, { min, max, breakpoints })` hook

### 1.2 配色与对比度

#### 当前状态

- 学术主题：深色背景 (`#0f172a`) + 浅色文字 (`#f8fafc`)
- 科普主题：浅色背景 (`#F0F9F7`) + 深色文字 (`#2D3436`)
- 每个场景有独立的渐变和强调色

#### 问题

| 问题 | 影响 |
|------|------|
| BulletList 硬编码 `color: "#cbd5e1"` 和 `accentColor: "#3b82f6"` | 科普主题下几乎不可见 |
| AnimatedText 硬编码 `color: "#e2e8f0"` | 浅色背景下不可读 |
| HighlightText 硬编码 `highlightColor: "#3b82f6"` | 忽略主题 |
| FormulaBlock 硬编码 `rgba(59,130,246,...)` | 忽略主题 |
| 无 WCAG 对比度验证 | 部分场景可能不满足可访问性要求 |

#### 优化方案

1. **所有组件接入主题系统**：BulletList、AnimatedText、HighlightText、FormulaBlock 必须通过 `useTheme()` 获取颜色
2. **对比度检查工具**：添加开发时的对比度验证（WCAG AA 标准 ≥ 4.5:1），在 Remotion Studio 中显示警告
3. **场景配色规范**：建立完整的语义化 token 体系（`text.primary`、`text.secondary`、`surface.emphasis` 等），避免直接使用颜色值

### 1.3 动画与缓动

#### 当前状态

- 入场：spring（damping: 14–15, stiffness: 120–180）或线性 interpolate
- 交错：18–22 帧间隔
- 退出：SceneWrapper 15 帧 opacity + translateY
- 场景间转场：fade/slide/wipe，15–25 帧

#### 问题

| 问题 | 影响 |
|------|------|
| SceneWrapper 退出使用固定 `-12px` translateY | 不同分辨率下退出效果不一致 |
| BulletList `translateX(50)` 未缩放 | 竖屏下偏移过大 |
| SceneWrapper 退出动画与 TransitionSeries 转场可能叠加 | 双重淡出效果 |
| Subtitle 使用 CSS `transition: "color 0.1s"` | 与 Remotion 帧驱动模型冲突 |

#### 优化方案

1. **所有动画值走 `s()` 缩放**：`translateX`、`translateY`、`blur` 等
2. **消除转场叠加**：SceneWrapper 退出动画与 TransitionSeries 只保留一个，或在 TransitionSeries 期间禁用 SceneWrapper 退出
3. **Subtitle 改用帧驱动动画**：用 `interpolate` 替换 CSS `transition`
4. **统一缓动配置**：将 spring 参数集中到主题配置中（`theme.animation.springConfig`），保证全局一致

### 1.4 图片与图表展示

#### 当前状态

- FigureScene：`objectFit: "contain"`，`maxWidth: "58%"/"95%"`，`borderRadius: s(14)`
- 带阴影和边框，从主题获取
- 缩放动画：0.95→1

#### 问题

| 问题 | 建议 |
|------|------|
| 无加载/错误状态 | 添加占位符和错误降级 |
| 无 Retina/高 DPI 处理 | 考虑 `Img` 的 `srcSet` 或更高分辨率源 |
| 纯白背景的图表在深色主题下突兀 | 添加图片背景适配（白色垫底 + 圆角） |
| 图片过小时空间浪费 | 自适应布局：小图放大、大图缩放 |

#### 优化方案

1. **图片加载状态**：添加 skeleton 占位 → 加载完成淡入 → 失败显示"图片加载失败"
2. **图表背景适配**：检测图片是否为浅色背景，在深色主题下自动添加白色底板
3. **智能图片布局**：根据图片宽高比自动选择水平/垂直布局，避免大量留白

### 1.5 公式渲染

#### 当前状态

- KaTeX `displayMode: true`，`throwOnError: false`
- `cleanLatex()` 清理 `\[...\]`、`$$...$$`
- `splitFormulaParts()` 分步展示
- 字号 38–52px 按公式长度自适应

#### 问题

| 问题 | 建议 |
|------|------|
| KaTeX 逻辑在 4 个文件中重复 | 统一到 `utils/katex.ts` |
| FormulaBlock 未被主场景使用 | 统一使用或移除 |
| FormulaOverlay `transform` 冲突 | `translateX(-50%)` 与 `translateY` 叠加可能异常 |
| InlineLatex `verticalAlign: "middle"` 对高公式失效 | 使用 `baseline` 或动态计算 |
| 每帧重新渲染 KaTeX | 用 `useMemo` 缓存 |

#### 优化方案

1. **统一 KaTeX 工具**：`renderKatexCached(latex, options)` + `cleanLatex(raw)` + `splitFormulaParts(latex)`
2. **渲染缓存**：`useMemo(() => renderKatex(formula), [formula])` 避免每帧重新渲染
3. **公式动画增强**：分步公式可以逐项高亮（当前项加色、前项变淡），而非简单的 opacity 切换
4. **公式尺寸上限**：超长公式自动缩小或换行，避免溢出

### 1.6 背景与视觉层次

#### 当前状态

- DynamicBackground：渐变 + 光球 + 粒子
- 学术主题：粒子 + 光球
- 科普主题：仅渐变

#### 问题

| 问题 | 建议 |
|------|------|
| ComparisonScene 和 RelationshipScene 未使用 DynamicBackground | 统一或提供替代 |
| 光球尺寸固定 800×800 未缩放 | 通过 `useScale` 适配 |
| 无视觉层次区分 | 前景/中景/背景缺少深度感 |

#### 优化方案

1. **所有场景使用 DynamicBackground**（或统一的场景背景系统）
2. **增强视觉深度**：添加微妙的景深效果（远景模糊、近景清晰），特别是在 figure 场景
3. **背景与内容呼应**：不同场景类型可以有不同的粒子/光球配置，而非统一方案

## 二、文本与旁白质量

### 2.1 叙事结构

#### 当前状态

Story Architect 基于论文内容生成场景池，LLM 规划叙事弧线：

```
title → overview (hook) → method → formula → figure → result → conclusion
```

#### 问题

| 问题 | 影响 |
|------|------|
| 降级为确定性场景列表时缺少叙事张力 | 退而求其次的视频结构平淡 |
| 无显式的"叙事弧线"校验 | 无法保证"引入→发展→高潮→收尾"的节奏 |
| 场景间过渡仅在 prompt 中要求 | 无结构化检查过渡质量 |

#### 优化方案

1. **叙事弧线评分**：在 Pacing Reviewer 中添加叙事弧线检查——是否有明确的 hook（overview）→ 发展（method）→ 高潮（result/figure）→ 收尾（conclusion）
2. **过渡语检查**：验证相邻场景旁白之间是否有自然的语义衔接（最后一句→下一场景第一句）
3. **降级策略增强**：确定性降级也应保留叙事弧线意识（如调整场景顺序让最重要的发现放在视频的 2/3 处作为高潮）

### 2.2 旁白风格一致性

#### 当前状态

4 种风格（default/academic/story/popsci），通过 prompt 指导。

#### 问题

| 问题 | 影响 |
|------|------|
| 多场景生成时风格可能漂移 | 前半部分口语化、后半部分学术化 |
| 风格一致性无校验 | 用户选择"故事风格"但某些场景回退为默认 |
| 术语一致性无保证 | "Attention"首次译为"注意力"，后面变成"注意力机制" |

#### 优化方案

1. **风格一致性评分**：Pacing Reviewer 中添加风格一致性检查——对比各场景旁白的语气词频率、句式结构是否匹配所选风格
2. **术语表**：Story Architect 阶段生成一个术语表（英文→中文译名），Scene Writer 必须遵循
3. **上下文传递**：Scene Writer 生成每个场景时，传入前一个场景的最后一句作为过渡参考

### 2.3 内容准确性

#### 当前状态

- Prompt 要求"不要编造数据，从论文摘要中提取"
- Result 场景的 baselines 由系统补充
- 专有名词保留英文

#### 问题

| 问题 | 影响 |
|------|------|
| 无 Faithfulness 校验 | LLM 可能"创造性"重述导致失真 |
| 数字/指标可能被 LLM 修改 | "97.3%" 可能变成"约 97%" |
| 方法描述可能过度简化 | 关键步骤被省略 |

#### 优化方案

1. **Faithfulness 检查**：添加后处理步骤，对比旁白中的关键数字/指标与 PaperSummary 中的原始数据，标记偏差
2. **数字锚定**：在 prompt 中要求保留原始数字精度，不做四舍五入
3. **关键实体对照**：检查旁白是否覆盖了 PaperSummary 中所有 importance ≥ 4 的概念
4. **引用标注**：在 data 字段中保留内容来源（如 `source: "abstract"` / `source: "section_3.2"`），便于溯源

### 2.4 中英文处理

#### 当前状态

- 中文优先策略，`_MIN_CHINESE_RATIO = 0.3`
- 英文论文也翻译为中文旁白
- 术语首次出现中英对照

#### 问题

| 问题 | 影响 |
|------|------|
| 中文检查阈值（30%）偏低 | 大量英文术语可能通过检查 |
| 无混合语言的排版策略 | 中英文字符间距不统一 |
| data 字段的中英文检查不够全面 | 某些字段可能遗漏 |

#### 优化方案

1. **提高中文比例阈值**：建议提高到 0.5–0.6，或区分"术语保留英文"和"整句英文"
2. **术语规范化**：自动检测首次出现的英文术语，确保有中文翻译
3. **排版优化**：中英文之间自动添加空格（half-width space），提升视觉一致性

## 三、语音合成质量

### 3.1 语音表现力

#### 当前状态

- Edge TTS，5 个中文预设 + 4 个英文预设
- 场景级 prosody：rate 和 pitch 微调
- `...` → `<break time="400ms"/>`

#### 问题

| 问题 | 影响 |
|------|------|
| Edge TTS 表现力有限 | 无法表达惊讶、强调、疑问等情感 |
| 场景级 prosody 粒度太粗 | 同一场景内语速恒定 |
| 停顿仅依赖 `...` 标记 | LLM 可能不标记或不准确 |

#### 优化方案

1. **句子级 prosody**：解析旁白中的语气标记（感叹号→提高 pitch、问号→升调、强调词→降速），生成更细粒度的 SSML
2. **显式停顿标注**：在 Scene Writer 输出中添加结构化停顿标注（`<pause:short>` / `<pause:long>`），而非依赖 `...`
3. **TTS 引擎升级路径**：预留切换到更高质量 TTS 的接口（如 Azure Neural TTS 的情感风格、Fish Audio 等）
4. **语速自适应**：根据内容复杂度自动调整语速——概念解释时放慢、过渡时加快

### 3.2 Word Timing 精度

#### 当前状态

- Edge TTS `WordBoundary` 事件提供 word timing
- 无事件时回退到按字符均匀分配
- 用于 Visual Director 的动画同步和字幕生成

#### 问题

| 问题 | 影响 |
|------|------|
| 字符均匀分配不准确 | 无 WordBoundary 时动画与语音不同步 |
| 中文 word boundary 粒度不一 | 有时按字、有时按词组 |
| 停顿时间未计入 timing | `<break>` 后的 timing 可能偏移 |

#### 优化方案

1. **Forced Alignment 后处理**：在 TTS 之后用 whisper 或 Montreal Forced Aligner 重新对齐音频与文本，获得更精确的 timing
2. **停顿时间补偿**：`<break>` 标签的时长应累加到后续 word 的 offset 中
3. **中文分词对齐**：使用 jieba 分词后与 TTS 输出对齐，提高中文 word boundary 的语义合理性

### 3.3 场景间音频衔接

#### 当前状态

- 每个场景独立生成一个 MP3
- pre/post padding：formula 1.0–2.0s，figure 1.0–1.5s，其他 0.5–1.0s

#### 问题

| 问题 | 影响 |
|------|------|
| 场景间可能有明显的音频拼接感 | 音量/音色不连续 |
| padding 是静音 | 转场时完全无声，感觉"断裂" |

#### 优化方案

1. **音量归一化**：对所有场景音频做 loudness normalization（如 -16 LUFS）
2. **淡入淡出**：场景首尾添加 50–100ms 的 fade in/out，平滑拼接
3. **转场音效**（可选）：添加微妙的 whoosh 或 tone 作为场景转场信号

## 四、注意力管理

### 4.1 三种注意力模式

#### 当前设计

| 模式 | 语义 | 典型场景 |
|------|------|----------|
| `voice_primary` | 语音主导，画面辅助 | title 开场、概念铺垫 |
| `visual_primary` | 画面主导，语音引导 | figure/formula 首次展示 |
| `synced` | 语音与画面同步 | method 步骤、result 对比 |

#### 问题

| 问题 | 影响 |
|------|------|
| 前端场景组件尚未充分使用 `attentionMode` | 模式切换不影响实际渲染 |
| attention markers 依赖 LLM 标注 | 标注可能不准确或遗漏 |
| 无观众注意力模型 | 缺少认知负荷控制 |

#### 优化方案

1. **前端渲染响应 attentionMode**：
   - `voice_primary`：画面元素保持静态或缓慢移动，不分散注意力
   - `visual_primary`：字幕淡化或隐藏，突出画面元素，语音音量降低
   - `synced`：高亮当前讲述的元素，字幕与语音同步
2. **Attention Marker 后验检查**：在 Visual Director 阶段验证 marker 的时间点是否合理（如 visual_primary 不应在无视觉元素时出现）
3. **认知负荷控制**：
   - 限制同时展示的视觉元素数量（已有：visual_primary ≤ 3）
   - 新元素出现后留出 2–3 秒再开始讲解
   - 复杂公式/图表使用"先展示→停顿→再解释"的节奏

### 4.2 视觉停顿

#### 当前状态

场景类型有不同的 `visual_pause_sec`：formula 5.0s、figure 4.0s、method 2.0s、result 2.0s。

#### 问题

| 问题 | 影响 |
|------|------|
| 停顿时间固定 | 简单图表和复杂图表用相同停顿 |
| 停顿期间画面完全静止 | 观众可能以为视频卡住 |

#### 优化方案

1. **自适应停顿**：根据图表复杂度（图片尺寸、公式长度）动态调整停顿时间
2. **停顿期间微动画**：添加微妙的呼吸动画（scale 1.0→1.01→1.0）或高亮扫描效果，保持视觉活力
3. **停顿提示**：在停顿期间显示微妙的"请观看"指示（如角落的眼睛图标或聚光灯效果）

## 五、节奏控制

### 5.1 时长约束

#### 当前状态

| 场景 | 时长范围 | 旁白字数 | 语速 |
|------|----------|----------|------|
| title | 5–10s | 15–35 字 | 3.5 字/秒 |
| overview | 15–35s | 60–120 字 | 3.5 字/秒 |
| method | 15–35s | 60–120 字 | 3.5 字/秒 |
| formula | 15–30s | 55–100 字 | 3.5 字/秒 |
| figure | 12–25s | 50–85 字 | 3.5 字/秒 |
| result | 15–32s | 60–110 字 | 3.5 字/秒 |
| conclusion | 10–22s | 40–80 字 | 3.5 字/秒 |

#### 问题

| 问题 | 影响 |
|------|------|
| 语速 3.5 字/秒 对所有场景一致 | 概念密集段落可能太快 |
| max_rounds = 1，重写机会少 | 复杂节奏问题可能无法在 1 轮内修复 |
| 总时长 120–300s 范围较大 | 短论文和长论文用同一范围 |

#### 优化方案

1. **场景级语速**：不同场景类型使用不同语速——formula/concept 放慢至 3.0 字/秒，overview/conclusion 保持 3.5 字/秒，result 加快至 4.0 字/秒
2. **增加重写轮次**：`max_rounds` 从 1 提高到 2，允许更充分的迭代
3. **自适应总时长**：根据论文长度和图表数量动态计算目标总时长，而非固定 120–300s
4. **节奏变化曲线**：在全视频层面控制节奏——开头稍慢（建立信任）→中段加速（高信息密度）→结尾放慢（总结强化）

### 5.2 场景比例

#### 当前状态

Pacing Reviewer 检查最长/最短场景比 ≤ 3。

#### 优化方案

1. **黄金比例**：introduction 类场景（title + overview）占总时长 15–20%，核心内容（method + formula + figure + result）占 60–70%，收尾（conclusion）占 10–15%
2. **信息密度平衡**：确保每 30 秒至少有一次视觉变化（新元素、场景切换、动画）
3. **"呼吸"节奏**：高信息密度场景后插入低密度场景（如 concept 或 analogy），让观众消化

## 六、字幕质量

### 6.1 当前状态

- 基于 word timing 实时显示
- 每行 18 字（竖屏）/ 28 字（横屏）
- 高亮当前播放的词

### 6.2 问题

| 问题 | 影响 |
|------|------|
| 每帧重新计算行分组 | 性能开销 |
| 无标点断句优化 | 可能在不自然的位置换行 |
| 字幕遮挡内容 | 无碰撞检测 |

### 6.3 优化方案

1. **智能断句**：优先在标点符号（句号、逗号）处换行，而非严格按字数
2. **行分组缓存**：`useMemo` 按 wordTimings 缓存，避免每帧重新计算
3. **自适应位置**：根据当前场景的内容区域，自动调整字幕位置（底部/顶部），避免遮挡关键内容
4. **渐进出现**：字幕随语音逐字显示（打字机效果），而非整行闪现

## 七、场景特定优化

### 7.1 Formula 场景

| 当前 | 优化 |
|------|------|
| 公式整体淡入 | 公式按组件逐步构建（先框架→再填充→最后等号右侧） |
| 解释文本同时出现 | 与公式同步：每个符号出现时旁白同步解释 |
| 固定停顿 5s | 根据公式复杂度（LaTeX token 数）动态停顿 |

### 7.2 Figure 场景

| 当前 | 优化 |
|------|------|
| 图片整体展示 | 添加"聚焦"动画：先全貌→放大关键区域 |
| caption 文字无动画 | 关键词高亮配合旁白 |
| 无标注指引 | 旁白提到"左下角"时添加箭头/高亮指引 |

### 7.3 Method 场景

| 当前 | 优化 |
|------|------|
| 步骤列表逐项出现 | 步骤之间添加流程箭头动画 |
| 当前步骤高亮 | 已讲完的步骤变淡（而非保持原色） |
| 内联公式静态展示 | 公式出现时添加微妙的脉冲效果 |

### 7.4 Result 场景

| 当前 | 优化 |
|------|------|
| 数据列表展示 | 添加柱状图/折线图动画（数字→图形化） |
| 数字静态显示 | 数字滚动动画（0→97.3%） |
| 对比无视觉强调 | 胜出指标用绿色高亮 + ↑ 箭头 |

### 7.5 Relationship 场景

| 当前 | 优化 |
|------|------|
| 节点同时出现 | 节点按叙述顺序逐个出现 |
| 边线静态 | 边线流动动画（虚线移动效果） |
| 布局仅 radial/tree/flow | 添加自动布局优化（基于节点数量选择最佳布局） |

## 八、整体质量保证机制

### 8.1 当前质量检查链

```
Extraction → Quality Gate (L1/L2/L3)
                              ↓
Script → Pacing Reviewer (duration/word_count/ratio)
                              ↓
TTS → Word Timing Check
                              ↓
Visual Director → Phase Validation
```

### 8.2 缺失的检查

| 检查 | 目的 | 建议实现 |
|------|------|----------|
| Faithfulness Check | 旁白是否忠实于论文 | 对比旁白关键数字/实体与 PaperSummary |
| Style Consistency | 全视频风格一致 | 对比各场景旁白的语气词频、句式 |
| Transition Quality | 场景间过渡自然 | 检查相邻场景首尾句的语义连贯性 |
| Visual-Audio Sync | 视觉与语音同步 | 验证 attention mode 切换点与画面变化对齐 |
| Cognitive Load | 认知负荷合理 | 检查信息密度不超过阈值 |
| Narrative Arc | 叙事弧线完整 | 验证 hook → 发展 → 高潮 → 收尾 |

### 8.3 端到端质量评估

建议添加最终的"质量评估"步骤，在渲染前综合评分：

```python
class VideoQualityScore(BaseModel):
    content_accuracy: float    # 内容准确性 (0-10)
    narration_quality: float   # 旁白质量 (0-10)
    pacing_balance: float      # 节奏平衡 (0-10)
    visual_coherence: float    # 视觉一致性 (0-10)
    attention_flow: float      # 注意力引导 (0-10)
    overall: float             # 综合分
    issues: list[str]          # 具体问题
    suggestions: list[str]     # 改进建议
```
